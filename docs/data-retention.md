# 개인정보 보유·파기 절차

**근거** 부록 A 개인정보처리방침 제3조·제7조 · 보안 체크리스트 A-3
**작성일** 2026-08-13
**책임자** 이영광 개발총괄이사 (개인정보 보호책임자)

---

## 왜 이 문서가 필요한가

부록 A 제3조는 문의 응대 정보를 **처리 완료 후 3년 보관 후 파기**한다고 공개 약속한다.
방침에 적어 두고 실제로 파기하지 않으면 **방침 위반**이 된다.

이 사이트는 별도 DB 를 두지 않으므로(→ `docs/deviations.md` B-1),
**수신 메일함이 유일한 공식 보관소**다. 따라서 파기도 메일함에서 이뤄진다.
누가·언제·어떻게 하는지 정해 두지 않으면 이행되지 않으므로 이 문서로 고정한다.

## 2. Slack 알림을 쓸 경우 반드시 할 것

Slack 알림은 편의 기능이지만 **개인정보 사본이 하나 더 생기는 것**이다. 사용한다면:

- [ ] 전용 **비공개 채널**을 만들고 필요한 인원만 초대한다
- [ ] 채널에 **메시지 보존 기간을 설정**한다 (권장: 90일 자동 삭제)
- [ ] 워크스페이스 전체 검색에 노출되지 않는지 확인한다

보존 기간을 설정하지 않으면 Slack 에 문의 내용이 무기한 남아 3년 파기 약속과 어긋난다.
설정이 어렵다면 **`SLACK_WEBHOOK_URL` 을 비워 알림을 끄는 편이 안전하다.**

## 3. 정기 파기 절차 (분기 1회)

담당: 개인정보 보호책임자 · 주기: 매 분기 첫 영업일

1. 메일함에서 **접수일 기준 3년 경과** 문의 메일을 검색한다
   - 검색 예: `subject:[홈페이지 문의] before:2023/08/13`
   - 접수 일시는 메일 본문의 `접수 일시` 줄에도 기록되어 있다
2. 대상 메일을 **휴지통이 아니라 영구 삭제**한다 (부록 A 제7조 — 복구 불가능한 방법)
   - 휴지통에 남아 있으면 파기가 완료된 것이 아니다
3. 채용 지원 메일은 **채용 절차 종료 후 1년** 경과분을 같은 방식으로 처리한다
4. 아래 이력표에 수행 사실을 기록한다

## 4. 이용자가 삭제를 요청한 경우 (부록 A 제6조)

정기 파기와 무관하게 **지체 없이** 처리한다.

1. 요청자 본인 확인 (요청 메일 주소와 문의 시 기재한 이메일 일치 여부)
   - 대리인 요청이면 위임장 확인
2. 해당 문의 메일을 영구 삭제. Slack 알림을 쓴다면 해당 메시지도 삭제
3. 처리 완료를 요청자에게 회신
4. 위 이력표에 "이용자 요청"으로 기록

## 5. 전제가 깨지는 조건 — 이때는 이 문서를 다시 쓴다

아래 중 하나라도 발생하면 보관 지점이 늘어난 것이므로 **1절 표를 갱신하고 부록 A 제5조에 수탁자를 추가**해야 한다.

- [ ] 문의 데이터를 DB(Supabase·Google Sheets 등)에 적재하기 시작할 때
- [ ] 이메일 API(Resend 등)로 발송 수단을 바꿀 때 — 발송 로그에 수신자·본문이 남는다
- [ ] 에러 트래킹(Sentry 등)을 도입할 때 — request body 스크러빙 설정 필수 (B-4)
- [ ] 분석 도구(GA4·네이버 애널리틱스)를 붙일 때
- [ ] 위 중 **국외 사업자**가 포함될 때 → 부록 A 에 **"개인정보의 국외 이전"** 조항 추가 (이전받는 자·국가·시점·항목·목적·보유기간 전부 고지)
