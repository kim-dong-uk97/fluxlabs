## A. 보안 체크리스트와 충돌해 기획서를 따르지 않은 항목

### A-1. 파트너 로고 슬롯을 `display:none` 이 아니라 **아예 렌더링하지 않음**

| | 내용 |
|---|---|
| 기획서 지시 | 5.1 S5 · 4.2 — "로고 이미지 슬롯은 마크업에 포함하되 `display:none` 처리해 추후 판단 시 즉시 활성화" |
| 실제 구현 | 로고 슬롯 마크업을 **생성하지 않는다.** 데이터에 `logo` 값이 있을 때만 렌더링되는 조건부 구조 |
| 사유 | `display:none` 은 화면에서만 안 보일 뿐 **브라우저 소스 보기로 전부 노출되고 검색엔진도 읽는다.** 같은 기획서 4.2·4.5·10장이 확정한 "협업 상대사 사명 전면 미표기", "병원 실명 비노출" 원칙과 정면 충돌한다. B2B 영업 사이트에서 발견되면 파트너사 신뢰 문제로 직결된다 |
| 확장성 | 손실 없음. `lib/business.ts` 의 `Partner` 타입에 `logo` 필드를 정의해 두었고, 공개 동의를 받은 시점에 값만 채우면 즉시 렌더링된다. 기획서가 의도한 "즉시 활성화"는 그대로 달성된다 |
| 근거 | 보안 체크리스트 A-1 |

> **승인 요청 사항**: 기획서 5.1 S5 의 `display:none` 지시를 "조건부 렌더링"으로 개정할 것을 제안합니다.

### A-2. 문의 폼 스팸 방지를 **허니팟 + 시간 트랩**으로 구현 (reCAPTCHA 미도입)

| | 내용 |
|---|---|
| 기획서 지시 | 5.5 — "reCAPTCHA v3(임계값 0.5) **또는** 허니팟 필드" |
| 실제 구현 | 허니팟 필드 + 렌더링~제출 경과시간 3초 미만 차단 + IP당 시간당 5건 rate limit + 서버 측 검증 |
| 사유 | 기획서가 택일을 허용한 항목이라 형식적으로는 이탈이 아니다. 다만 **선택 근거를 남긴다** — reCAPTCHA 를 붙이면 방문자 전원의 IP·쿠키가 구글로 전송되어 **부록 A 제5조 처리위탁 표에 수탁자 추가 + "개인정보의 국외 이전" 조항 추가**가 발생한다. 월 5건 목표 사이트가 감당할 법적 부담이 아니다 |
| 잔여 위험 | 이 사이트만 노린 맞춤 봇은 통과할 수 있다. 실제 스팸이 발생하면 폼 컴포넌트만 수정해 reCAPTCHA 를 얹을 수 있다 |
| 근거 | 보안 체크리스트 B-1 |

## B. 진행 중 결정으로 변경한 항목

### B-1. 문의 데이터 저장소를 **두지 않음** — 수신 메일함이 공식 보관소

| | 내용 |
|---|---|
| 체크리스트 지시 | A-3 — "서버리스 함수 → ① 저장소 적재 + ② 알림 발송 **두 가지를 모두** 수행" |
| 실제 구현 | 메일 발송(+Slack 알림)만 수행. 저장소 어댑터 **인터페이스만** 정의 (`lib/storage/types.ts`) |
| 사유 | 법적 의무는 "3년 뒤 파기"이지 "DB 적재"가 아니다. 체크리스트가 우려한 것은 *"개인 메일함에 흩어져 파기 방법이 없는 상태"* 인데, **수신처를 `info@fluxlabs.co.kr` 한 곳으로 고정**하면 해소된다. 월 5건 목표면 3년치가 180건 수준이라 메일 라벨 검색으로 관리 가능하다. DB 를 붙이면 개인정보 보관 지점이 2곳으로 늘어 파기 대상만 많아진다 |
| 조건 | **파기 절차를 문서로 남겨야 한다** → `docs/data-retention.md` |
| 전환 | 문의량이 늘면 `InquiryStore` 인터페이스 구현체 하나만 추가하면 된다. 그때 부록 A 제5조에 수탁자 기재 필요 |

### B-2. 메일 발송은 **SMTP 유지** (이메일 API 미도입)

| | 내용 |
|---|---|
| 기획서 지시 | 5.5 · 7.1 — "서버리스 함수 + SMTP" |
| 실제 구현 | SMTP 유지. 단 **발송 수단을 인터페이스 뒤에 격리** (`lib/mail/`) |
| 검토 경과 | 이메일 API(Resend 등) 전환을 검토했으나, 회사가 이미 쓰는 `info@fluxlabs.co.kr` 계정으로 보내면 **처리위탁 수탁자가 늘지 않는다**는 이점이 있어 SMTP 를 유지하기로 결정 |
| 잔여 위험 | SMTP 는 발송 실패를 추적할 수단이 없다. 완화책으로 기획서 5.5 가 정의한 "실패 시 에러 메시지 + 대표 이메일 직접 안내"를 구현하고, 서버 로그에 실패 사유를 남긴다(개인정보는 제외) |
| 전환 | `lib/mail/` 에 구현체 파일 하나 추가 + `MAIL_TRANSPORT` 환경변수 변경. 호출부 수정 불필요 |

### B-3. 카피는 기획서 원문 **그대로 유지**

검토 과정에서 사실관계 확인이 필요한 문장 2건을 발견했으나, **수정하지 않고 원문을 유지**하기로 결정했다. 아래는 확인용 기록이다.

| # | 위치 | 문장 | 확인이 필요한 이유 |
|---|---|---|---|
| 1 | 4.3 확장 계획 | "파트너사는 3년 내 **1,000개 매장** 규모의 네트워크 구축을 목표로" | 제3자의 사업 계획을 우리 사이트에서 단정한다. 같은 문서 4.3 이 "유추 가능한 서술 배제"를 지시하는데 규모를 적으면 특정 가능성이 올라간다. 10장 "향후 계획의 단정적 서술" 항목과도 관련 |
| 2 | 4.5 현재 상태 | "종합병원에 **실제 도입되어 운영 중**" | 4.5 는 "실증/테스트베드 문구 비노출"을 확정했는데 "운영 중"은 그보다 강한 주장이다. B2B 상대가 확인 가능한 사실이므로 10장이 경고한 신뢰 손실 위험 |

> **대표·기획 확인 요청**: 두 문장을 그대로 게시할지 판단 부탁드립니다. 표현 조정이 필요하면 해당 자리를 대체할 구조(기술 과제 블록)는 이미 만들어져 있습니다.

## E. 전달받은 문서·자산 자체의 불일치 — **확인 요청**

### E-1. 로고 SVG 의 파랑이 브랜드 지정 컬러와 다름 ⚠️

| | 값 |
|---|---|
| 기획서 8.2 · CI 컬러 시스템 가이드 | Flux Navy **`#2A4269`** (RGB 42/66/105) |
| 전달받은 SVG 15종의 blue 변형 | **`#191970`** (RGB 25/25/112 — CSS 명명색 `midnightblue`) |
| 영향 | 두 색은 눈에 띄게 다르다. `#191970` 은 더 어둡고 보라 기가 돈다 |
| 현재 처리 | **문서상 브랜드 지정 컬러 `#2A4269` 를 따랐다.** 기획서 8.2 가 "변경 불가"로 지정했고 CI 가이드 본문도 같은 값이기 때문 |
| 확인 필요 | 어느 쪽이 정본인지 디자이너 확인 후, **틀린 쪽 자산 또는 가이드를 수정**해야 한다. 지금은 로고 SVG 원본과 웹 구현 색이 다른 상태다 |

> 검증 방법: `Downloads/homepage/FLUXLABS LOGO(svg)/**/*-blue.svg` 의 `fill` 속성 확인. 15개 파일 전부 `#191970`.

### E-2. 로고 파일명 규칙 불일치

기획서 8.1 이 이미 지적한 사항이다. `compact - blue.svg` 만 소문자로, 나머지는 `Compact - Black.svg` 형태다. **웹 구현에는 영향 없다** — SVG 패스를 컴포넌트로 인라인화했기 때문에 파일명을 참조하지 않는다. CI 키트 자체의 정리 사항으로만 남긴다.

### E-3. 최소 사이즈 기준 미명시

9.2 F 항목. 원본 가이드의 디지털 최소 크기가 가로폭 기준인지 높이 기준인지 명시가 없다. **가로폭 기준으로 가정**해 `components/Logo.tsx` 에 개발용 경고를 넣었다 (권장 최소치 미만이면 개발 모드에서 콘솔 경고). 디자이너 확인 후 값 조정 필요.

## F. 기획서에 없던 구현 판단 (참고)

| 항목 | 판단 |
|---|---|
| 법적 문서 렌더링 | 부록 개발 참고는 **MDX 관리**를 권장하나, 문서가 2건이고 개정 빈도가 낮아 **구조화된 TSX** 로 작성. MDX 툴체인 도입 비용 대비 이득이 없고, raw HTML 을 쓰지 않아 `dangerouslySetInnerHTML` 금지 원칙(B-6)에도 부합 |
| JSON-LD 삽입 | 통상 `dangerouslySetInnerHTML` 을 쓰지만 B-6 에 저촉된다. `<`, `>`, `&` 를 JSON 유니코드 이스케이프로 치환해 **금지 API 없이** 구현 (`lib/json-ld.ts`). 빌드 산출물에서 파싱 정상 확인 |
| 폰트 | 7.3 "Pretendard Variable (subset)" → **동적 서브셋(unicode-range 92분할)** 적용. 브라우저가 실제 사용 구간만 내려받는다 |
